## 8. Failure-and-recovery acceptance matrix

Use fake clocks/deferred responses for deterministic unit and integration checks; use real browsers/devices for native prompts, suspension, focus, and history behavior. These checks supplement the happy-path feature checks above.

| Scenario | Required outcome |
| --- | --- |
| Bust at 9 seconds into a still-pending startup location probe | Share the outstanding native request; preserve the startup deadline and the bust's own five-second maximum wait; do not stack prompts or extend the eight-second context budget. |
| Location fails, newest own bust has null coordinates, another user has a newer valid bust | Use the acting user's newest earlier valid location; never take the other user's location. Fresh region lookups remain bounded. |
| Weather hangs while geocoding succeeds and Bitcoin uses a fallback provider | Keep valid partial results, abort/ignore overdue work, and submit context by its deadline without waiting for every provider. |
| Account A logs out and B logs in during context collection or a profile fetch | No A action writes as B, and no stale response restores A's views or cache. Any already-sent A write is handled only under its captured identity. |
| Server inserts the bust, but its response is lost | Show pending confirmation, find the same action UUID, and converge to one displayed/saved event. Do not turn a retry into a second event. |
| App becomes hidden before submission, or after submission but before confirmation | Cancel an unsent action; reconcile an already-sent action on return. Do not execute an old unsent bust automatically after suspension. |
| New award/update/delete arrives while a history page is pending | The fetched page cannot undo the event; counters/list/comparison converge after reconciliation, without duplicate notifications. |
| Only the recent 300 busts are loaded when a new bust is confirmed | Server reconciliation still runs; lifetime statistics remain visibly incomplete until history finishes. |
| Achievement popup opens over another user's profile, then Back/Escape is used | Progress belongs to that user, only the top layer closes, the profile's scroll/focus is restored, and the active surface stays sharp. |
| Logout or account deletion occurs while an overlay is recorded in browser history | Back/Forward does not restore stale account content or trap the user on an unusable modal. |
| Native permission dialog outlives the application's deadline | The app stops waiting and does not promise it closed the native prompt; late callbacks do not change a committed bust. |
